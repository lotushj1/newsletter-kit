# 個人資料處理

> **對外公開的隱私權政策文字必須由發行者自己定稿。** 這份文件只說明系統存了哪些資料、維運者怎麼處理單一個人的要求，不是法律意見；保留期限也要由發行者決定後填入下表。

## 處理單一個人的要求

以下都用後台操作；括號裡是對應的 Admin API（`Authorization: Bearer <ADMIN_TOKEN>`）。修改、刪除、匯出都會留在後台「操作紀錄」，紀錄裡不寫對方的 email。

| 要求 | 怎麼做 | 注意 |
| --- | --- | --- |
| **查看** | 「名單」搜尋 email（`GET /api/admin/subscribers?search=<email>`），可看到 email、名稱、狀態、標籤、資料夾、來源、加入／確認／退訂時間與備註欄（例如退信原因） | 他收過哪些信要逐封看電子報的寄送紀錄（`GET /api/admin/campaigns/:id/deliveries`）；目前沒有「一個人的全部紀錄」查詢 |
| **更正** | 「名單」編輯（`PATCH /api/admin/subscribers/:id`，可改 `email`、`name`、`tags`、`folderId`、`status`） | 改 email 不會改到舊寄送紀錄裡的 email |
| **匯出給本人** | 目前沒有單人匯出。用「匯出 CSV」（`GET /api/admin/subscribers/export.csv`）取出他那一列，再加上寄送紀錄的查詢結果 | 整份匯出含所有人的資料，取完後刪掉暫存檔 |
| **退訂（不想再收信）** | 狀態改成「已退訂」（`PATCH … { "status": "unsubscribed" }`） | **優先用退訂，不要用刪除**：這一列留著，之後匯入同一個 email 只會更新名稱、標籤、資料夾，不會改回訂閱 |
| **刪除（要求刪資料）** | 「名單」刪除（`DELETE /api/admin/subscribers/:id`） | 見下方「刪除不會刪到的東西」 |

### 刪除不會刪到的東西

刪除只移除名單裡的那一列，**不會**：

- 刪掉寄送紀錄（每一筆都存著收件 email）與追蹤事件（存著訂閱者 id）；
- 把他加進排除名單；
- 刪掉寄信服務、Notion、備份檔與 InsForge 專案備份裡的資料。

所以刪除之後，同一個 email 如果又被匯入、或從其他來源同步進來，會被當成新的訂閱者寄信。系統目前**沒有**讓維運者手動把某個 email 加進排除名單的功能；排除名單只會因為退信、檢舉，或「名單裡沒有這個人時按了退訂」而寫入。對方同時要求「不要再寄」與「刪除資料」時，做法要由發行者決定：保留一列「已退訂」並清空名稱、標籤（資料最少），或刪除並接受日後可能被重新匯入的風險。寄送紀錄、備份與第三方的資料要另外處理，並在回覆對方時說明。

## 系統存了哪些資料

| 資料類別 | 內容 | 存在哪裡 | 保留期限（由發行者決定） |
| --- | --- | --- | --- |
| **訂閱者** | email、名稱、狀態（待確認／已訂閱／已退訂／退信）、標籤、資料夾、來源、加入／確認／退訂時間、備註（退信原因、匯入來源） | `nk_subscribers`（SQLite：`subscribers`） | `［待填］` |
| **同意紀錄** | 來源（表單、匯入、Notion 等）、加入時間、確認時間（double opt-in 點確認信的時間）。**沒有**存 IP、瀏覽器或當時表單的同意文字 | 同上 | `［待填］`；需要更完整的同意證明時要另外加欄位 |
| **寄送紀錄與回報** | 收件 email、電子報、狀態（待寄／寄送中／已寄出／失敗／略過）、嘗試次數、錯誤訊息、寄信服務的訊息 id、寄出時間；退信與寄信服務回報的狀態也寫在這裡 | `nk_deliveries`（SQLite：`deliveries`） | `［待填］` |
| **追蹤事件** | 開信、點擊（含點擊的網址）、退訂事件：電子報、訂閱者 id、寄送紀錄 id、時間。**沒有**存 IP 或瀏覽器 | `nk_events`（單列快照 driver 另有 `nk_event_inbox` 暫存） | `［待填］` |
| **排除名單** | `suppression:<小寫 email 的 SHA-256>` → `bounce`／`complaint`／`unsubscribe`（解除時是空字串）。不存明文 email，但拿 email 算一次 hash 就能對上，仍屬個人資料 | `nk_settings`（SQLite：`settings`） | **不可刪**（見下節） |
| **操作紀錄** | 時間、執行者（後台 Google 登入的 email，或 `admin-token`）、動作、對象 id、簡短說明。不存訂閱者 email、金鑰或內文 | `nk_audit_log`（SQLite：`audit_log`；記憶體類 driver 只留最近 500 筆） | `［待填］`；資料表只能新增，要清舊紀錄得另寫 migration |
| **伺服器紀錄** | 部署平台（例如 Vercel）的執行紀錄。少數紀錄會帶收件 email：`dry_run 寄信`、`確認信寄送失敗`、Notion 同步結果 | 部署平台 | 依平台設定 `［待填］` |
| **備份** | 逐表匯出檔、InsForge 專案備份、單列快照 driver 的每小時歷史版本（72 份）；內容是上面全部 | 見 [備份與還原](backup-restore.md) | `［待填］`；到期刪除 |

資料也會送到第三方：

- **寄信服務**：收件 email 與信件內容（每封信）、確認信。
- **Notion**（有設定 `NOTION_TOKEN` 時）：email、訂閱狀態、來源、訂閱日。
- **AI 服務**（有接上而且使用「整理名單」等功能時）：被選取的人的名稱、狀態、標籤、資料夾與來源（不含 email），以及電子報內容。

這些服務各自的保留與刪除方式要寫進隱私權政策。

## 防止再寄給退訂的人：必須保留的資料

退訂、退信、檢舉的人之後不能再收到信。系統靠兩樣東西判斷：

1. **名單上的狀態**：已退訂、退信的人不在寄送對象裡。
2. **排除名單的 hash**：寄送時每個收件人都會再查一次排除名單；退信、檢舉，以及名單裡找不到的人按了退訂，都會寫進去。名單被清空、從舊備份還原或重新匯入時，靠這一層擋住。

所以：

- 刪除舊資料或清理名單時，**不要刪 `suppression:` 開頭的設定**，也不要把已退訂、退信的人整批刪掉後再重新匯入。
- 本人重新訂閱並點了確認信，「退訂」這種排除會自動解除；退信與檢舉不會解除。
- 保留期限到期要清理訂閱者資料時，至少保留排除名單的 hash，讓之後的匯入仍然會跳過這些地址。
